# 0002: CI-only builds and automatic releases

Status: accepted, 2026-11-14

## Context

The developer works from a phone (Termux). There is no desktop, Android
Studio or local Gradle.

## Decision

- All compilation, tests, Lint, Detekt and packaging run on free GitHub
  Actions runners.
- The Gradle wrapper was generated by a workflow (`bootstrap-wrapper.yml`),
  which runs when `gradle/wrapper-version.txt` changes.
- A release is published automatically when `version.txt` changes on `main`.
  The workflow creates the `v<version>` tag, so no manual tagging is needed.
  Versions containing `-` are pre-releases.
- Release signing uses a keystore stored in GitHub Secrets
  (`KBOARD_KEYSTORE_B64`, `KBOARD_KEYSTORE_PASSWORD`, `KBOARD_KEY_ALIAS`).
  The keystore is never committed and `.gitignore` blocks common key files.
- `versionCode` is the workflow run number, which always increases.

## Consequences

- Feedback is only as fast as a CI run, so changes should be small.
- Losing the keystore means updates cannot be signed with the same key.
  Play App Signing is planned so the stored key becomes a replaceable upload
  key.
- Code shrinking (R8) is not enabled yet and will be added with keep rules
  once there is code to protect.
